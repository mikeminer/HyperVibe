01 introduction

What is HyperVibe?

HyperVibe is the backend for agentic perpetuals trading. Just as infrastructure platforms give developers a database, auth, and storage without making them build those systems from scratch, HyperVibe gives an AI trading agent a live Hyperliquid connection, a scheduling system, a strategy memory, an audit trail, a monitoring loop, and a permission gate — without you having to build any of it.

You describe what you want to trade and why. The agent figures out how. The harness makes sure it runs reliably, accountably, and only as far as you've permitted.

🔌
Live Hyperliquid awareness
20 built-in tools covering execution, real-time prices, candles, indicators, funding rates, orderbook depth, vault data, and account state. The agent never reasons from stale training data.
🧠
Strategy memory that persists
The agent doesn't start from zero each session. A written Playbook anchors every decision — consistent rules, consistent judgement, isolated P&L tracking.
⏱️
Runs on its own schedule
Set a trigger once. The agent wakes itself up, reasons from live data, and acts — without you being present. Hyperliquid trades 24/7; HyperVibe monitors 24/7.
🔒
No trade without your consent
A code-level approval gate sits in front of every execution. Every trade recommendation arrives as a structured card with full reasoning. One click to approve or reject.
02 architecture

The Harness

The word "harness" is deliberate. A harness doesn't replace the horse — it channels its capability into something controllable, directed, and safe. HyperVibe does the same for Claude.

An LLM on its own is powerful but directionless for trading. It has no state, no time, no Hyperliquid connection, no memory of what it did yesterday, and no guardrails on what it can do next. The harness provides all of that as a set of interlocking primitives.

Signing

HyperVibe implements Hyperliquid's L1 action signing natively using ethers v6 and msgpackr. Actions are hashed via keccak256(msgpack(action) | uint64BE(nonce) | vaultAddress) and signed as EIP-712 Agent type against Hyperliquid's L1 domain (chainId 1337).

Your private key never leaves your machine. The signing happens locally before the signed payload is sent to Hyperliquid's exchange endpoint.

02 primitive

Heartbeat

Continuous market monitoring without continuous LLM inference. A lightweight loop that wakes the agent only when something matters.

Hyperliquid trades 24/7. Heartbeat monitors 24/7. But it does so cheaply — Claude Sonnet only runs when a trigger condition actually fires. Everything else is evaluated in pure JavaScript or via Claude Haiku (yes/no only).

01
Tick Interval fires
Every 30 seconds. Hyperliquid is 24/7 so Heartbeat never slows down.
02
Snapshot Prices fetched
Mid prices fetched only for coins referenced in active triggers. Not the whole market — just what's being watched.
03
Evaluate Triggers checked
Code triggers evaluated in pure JS (zero cost). LLM triggers sent to Claude Haiku for a yes/no answer (minimal cost). Cron triggers fire on their schedule.
04
Fire or stand down
If a condition fires: execute hard_order immediately, or wake Claude Sonnet with a reasoning_job. If nothing fires: quiet tick, no LLM cost.

03 primitive

Triggers

The automation primitive — every autonomous action originates from a trigger. A trigger is a condition and an action. When the condition becomes true, the action fires.

Condition modes

ModeWhen it firesTypical use
codeWhen a JavaScript expression evaluates to true against the live price snapshotStop-loss, take-profit, drawdown guard
timeOn a cron scheduleMorning scans, position reviews, EOD closes
llmWhen Haiku answers "yes" to a natural language questionInstinct-based conditions — sentiment, unusual movement

Action types

TypeWhat happensAgent involved?Typical use
hard_order Trade executes immediately — no reasoning, no approval queue. Pre-authorised at trigger creation. No Stop-losses, take-profits, emergency closes
reasoning_job Claude Sonnet wakes with trigger context and Playbook loaded, analyses the situation, and may queue approvals. Yes Morning scans, position reviews, event-driven analysis

Example trigger stack — HYPE Momentum

TriggerConditionAction
HYPE Stop Losscode — prices["HYPE"] <= 24.50hard_order SELL MARKET (close long)
HYPE Take Profitcode — prices["HYPE"] >= 32.00hard_order SELL MARKET (close long)
Portfolio Monitortime — 0 * * * * (hourly)reasoning_job — review positions, check funding
High Funding Alertllm — "Is HYPE funding rate above 0.1% per hour?"reasoning_job — evaluate whether to close long
Morning Scantime — 0 8 * * *reasoning_job — find best setups for the day
◈ hard_order vs reasoning_job: For stop-losses, always use hard_order. A stop-loss that waits for Claude to wake up, analyse, and queue an approval is not a stop-loss — it's a wish. The consent for a hard_order is given when you create the trigger.
04 primitive

Permissions

The trust primitive. A code-level approval gate that ensures no money moves without recorded consent.

Three levels of consent

ModeWhen givenWhere recorded
Trade-levelAt execution time — you approve each trade from the UIApproval record in SQLite — Approve / Reject
Trigger-level (pre-auth)When you create a hard_order trigger — you specify the exact condition and trade upfrontTrigger record — condition + tradeArgs
Autonomous (Playbook)When you define Playbook guardrails — max capital, max loss, circuit breakersPlaybook document — mandate boundaries

Every approval card shows the exact trade parameters plus the full reasoning the agent used to reach its recommendation. This is not a chat reply — it's a structured, timestamped record.

05 primitive

Playbooks

The agent's operating manual. A written strategy document that anchors every decision made on its behalf.

Every new LLM session starts from zero. Without a Playbook, ask the agent whether to buy HYPE today, close the tab, ask again tomorrow — and you might get a different answer. A Playbook fixes this. It is loaded as context on every run — whether triggered by a schedule, a price condition, or a live chat.

What a Playbook contains

SectionWhat it capturesExample
Investment thesisWhy you're trading this and what you believe"HYPE is undervalued relative to its market share. Long bias, target 3–5% moves."
Rules and constraintsWhat the agent must and must not do"Max 3x leverage. Never risk more than 1% equity per trade. Close all if daily drawdown > 3%."
Entry and exit approachHow the agent identifies and sizes trades"LONG: RSI < 40 on 4h, price above EMA21. Size = 1% equity / (entry - SL)."
Capital allocationHow much USDC is deployed and split"Slot A: $2,000 · Slot B: $2,000 · Reserve: $500 (never deployed)"
✦ You don't write Playbooks from scratch. Describe your strategy in chat — the agent shapes it into a structured document, then you approve it and it becomes the operating manual.
06 primitive

Learnings

The agent's audit trail and compounding memory. An immutable record of every trade, every decision, and everything distilled from both.

Every fill is logged with: coin, side, size, executed price, fee, closed PnL, and the reasoning the agent wrote at the moment of entry. You can always audit exactly why it made any decision.

Beyond accountability — without a record of what worked and what didn't, the agent makes the same mistakes indefinitely. Observations distilled from the journal feed forward into Playbook refinements over time.

Full Data Flow

How a complete autonomous Playbook run flows through all six primitives — from Heartbeat tick to executed trade.

01
Heartbeat deterministic
Tick fires. Mid prices fetched for all watched coins. Trigger condition evaluated — e.g. hourly cron 0 * * * *.
02
Trigger fires
Condition met. Trigger record updated. Agent instance started with trigger context and Playbook ID.
03
Playbook loaded
Agent receives the full Playbook document and recent Learnings as context. It knows its mandate, rules, and capital allocation.
04
Market Tooling tool calls
Agent calls get_positions, get_price, compute_indicators, get_funding_rate. Synthesises a decision — trade or stand down — with full reasoning.
05
Permissions gate
Signals fire. Agent calls place_order with full reasoning. Trade queued in the approval gate. Approval card appears in your UI (or pushes to Telegram — coming soon).
06
Broker executed
You approve. EIP-712 signature computed locally. Order sent to api.hyperliquid.xyz/exchange. Fill confirmed.
07
Learnings logged
Fill written to the trade journal with coin, size, executed price, fee, closed PnL, and the reasoning from step 04. Tagged to the active Playbook.
